# M7 bounded coverage-guided campaign

22 November 2026. Native Linux x64 / Swift 6.4.2 / system Clang 23.1.5.
The existing authorised host and installed runtimes are used; no installation,
service change, VM or container is introduced. Runtime sources match the
validated UTF-8 candidate (`8ab9786`, archive-only follow-up `b37a3ca`).

## Instrumentation and actual execution

The installed Swift distribution's direct sanitizer-link path is incomplete:
its fuzzer link requests an unavailable bundled UBSan archive. System Clang
already provides its fuzzer and UBSan archives. The
[development runner](../../../Tools/ParserStressProbe/Fuzzing/run-linux.py)
therefore compiles the library and standalone callback with Swift
`-sanitize=fuzzer`, Debug/`-Onone` and assertions enabled, then links those
existing system archives separately. Runtime/archive and executable digests
are retained. No runtime file is downloaded, patched or copied into a compiler.

Library object symbols verify coverage instrumentation. Execution reports
**17,809 inline 8-bit counters** and completes a **180-second requested
campaign in 181.276 seconds** with exit zero:

| Reported metric | Result |
| --- | ---: |
| Executed units | 3,510 |
| Final libFuzzer `cov` / `ft` | 3,802 / 18,199 |
| New units added | 785 |
| Peak RSS reported by libFuzzer | 53 MiB |
| Retained corpus files on disk | 732 |
| Crash artifacts / invariant failures / timeouts | 0 |

These are libFuzzer's own counters/features, **not line-coverage percentages**.
The in-memory corpus summary and on-disk file count need not agree; the receipt
records the actual retained files and every file's hash. Inputs are capped at
4,096 bytes, with seven authored initial seeds, seed `7348327`, five-second
per-input timeout, 2 GiB RSS limit and a separate 240-second whole-campaign
process-group bound. Builds/linking have their own bounds. Failed commands or
timeouts cannot produce a passing receipt.

Each accepted input runs CommonMark, GFM and both with all five M5 extensions,
with syntax details off/on. Assertions check original-byte preservation,
semantic/diagnostic/fallback/policy invariance, absence of invalid extension
results, public document revalidation, standard UTF-16 replacement decoding,
full HTML agreement and reverse-requested progressive group equality. All
**45 runtime/manifest/harness source hashes** match before/after and the current
checkout. The campaign runs after all x64 timed/resource work has finished.

## Reproduction and evidence

With the existing compatible Linux tools and a new output directory:

```sh
python3 -I Tools/ParserStressProbe/Fuzzing/run-linux.py \
  --output /tmp/gmsetzer-parser-fuzz --seconds 180
```

Follow the owner's approval requirement before long campaigns. The
[data directory](../../BenchmarkData/m7-fuzz-2026-11-22/) retains every phase's
command/result/log, source/runtime/executable digests, exact harness source,
the complete final corpus and its per-file hashes. Task paths in logs and
receipts are replaced; the corpus bytes remain unchanged. Build products and
compiler-runtime binaries are not committed or release assets.

## Limits

This is a short, bounded **coverage-guided** campaign, distinct from the earlier
1,024-input deterministic stress test. Neither proves unbounded hostile-input
complexity or absence of every bug. This Linux run does **not** enable
AddressSanitizer: its instrumentation is not described as ASan evidence.
The separate Mac ASan suite (252 tests) and bounded ASan stress (8,192 parses)
retain their actual scope in the [UTF-8 report](utf8-2026-11-22.md). The callback
is development-only and does not enter the root package or public library API.
Longer campaigns, larger inputs and further profiles remain useful follow-ups;
owner acceptance/merge and release publication are separate.
