# GMSetzer 0.7.0 — draft source-only preview notes

Draft only: no `v0.7.0` tag or release is published. The reviewed M7 candidate
still reports `0.7.0-dev.1`; final release identity, exact merged commit, release
CI and source-archive/consumer checks must be prepared before publication.
The latest installable published preview remains 0.6.0.

This preview is intended to carry M7's measured performance and hardening work
over 0.6.0, preserving the Markdown grammar, portable APIs, source coordinates,
safe-default HTML, optional annotations and progressive-output contract.

- Reuse parser-local traversal/emission buffers and one token arena instead
  of per-item token allocations. The focused large emphasis annotation case
  improves by 75–77%, with 262,219 → 94 allocation requests on the measured Mac.
- Compact private inline links/brackets and reserve emission batches with
  geometric growth: 31.21% less gross requested traffic in the 256 KiB bracket
  case, with broadly maintained timing.
- Reuse already validated canonical plain-paragraph trees when no inline work
  remains. The compatible malformed 256 KiB case improves 12.812 → 10.297 ms
  and gross requested bytes fall 53.05% on M2.
- Retain all 652 CommonMark / 672 GFM protected examples and exact public
  node/token snapshots. Add explicit C UTF-8 validation controls, current native
  Mac/x64 benchmark/resource evidence, minimum Swift 6.2 CI and bounded ASan/
  coverage-guided robustness checks.

The library remains pure Swift without runtime dependencies. C and benchmark
tools are development-only. Matching repaired HTML does not make malformed-
byte source-coordinate work identical to C; general C parity is not claimed.
Requested allocation traffic is not retained heap or peak RSS. Parsing still
precedes progressive output, giant blocks remain indivisible, and short fuzzing
does not establish correctness for every input. Consumer UI/device acceptance
and M8 API/DocC/1.0 work remain separate.

See [candidate readiness](../M7Readiness.md), [measurements](../Benchmarks.md)
and [release procedure](../Releasing.md). Publication requires the owner's
separate confirmation. Releases contain source only, with GitHub's automatic
ZIP/tar.gz archives and no uploaded build artifacts.
